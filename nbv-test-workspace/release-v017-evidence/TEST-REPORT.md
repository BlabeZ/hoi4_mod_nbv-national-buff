引擎测试使用独立测试目录，在 1936 德国自动触发测试事件。正式模组没有 on_startup 测试事件或注入精神。测试附加模组不进入安装描述符和发布包。

0.1.7 按用户 Markdown 选择并重排 519 个显示词条：忽略 111 个空条目，删除 16 次重复出现，只保留首次位置；用户确认粘连的情报行拆为两条。基础 559 个稳定 ID、数值格式和来源定义保留，未入选的 40 个 ID 不进入实时或后备 GUI 数组。静态核对全部显示顺序，隔离引擎核对每个实际单元格，并继续执行 559 项基础读数及来源回归。

0.1.6 将 Modifier Icons 汉化版的图标接入全部 559 项名称与悬停标题。静态检查核对独立精灵、DDS 路径、哈希、帧数和名称框容纳尺寸；引擎日志逐项比对图标标记及原名称，原有读数与来源检查继续执行。该证据不等于游戏截图中已目视确认图标位置或透明边缘。

读数测试先记录国家值，再添加国家精神，向每个待测键注入已知的 +0.125。552 项在组合注入中匹配；另外 7 项因稳定度／战争支持度等联动改用逐项注入后匹配。删除测试精神后，通过相同的动态本地化分发器读取名称与数值，再检查六页非零项目数量。

**这证明这些键能读取国家修正并反映已知变化；不证明所有来源、颜色方向、舍入方式或窗口像素已经验收。** `runtime_read_validated=true` 仅指此处的国家修正读取测试。研究目录中的 false 是制作前快照，格式表中的 runtime_validated=false 仍表示格式未经过视觉核验。

0.1.1 另外对统一列表的 559 个实际单元格逐一核对页、区、行、列、ID、名称与数值；静态模型覆盖 1018 组高低区数量边界。来源样本为苦涩的失败者、有限征兵、有限出口和元首：检查来源移除后行消失、恢复后行出现，以及国家合计差值。领袖测试在测试事件内显式重算缓存，正式模组不强制重算游戏修正。来源表全部候选没有逐一运行验证，4 个样例通过不能等同于 15972 条来源全覆盖。

0.1.3 扩展来源测试包含顾问任职／特质移除／恢复／解聘、同人不同职位隔离、科技、主学说、子学说阶段、锁定奖励、轨道里程碑、固定动态修正和活动决议。核对国家数值增量、来源行实际打印的数值、完整词条提示包含来源，以及失效后来源隐藏。每阶段明细保存在引擎报告 expanded_source_checks；候选来源并未逐一运行验证。

0.1.4 新增变量动态民族精神、政体，以及阵营章程和宗旨来源。动态民族精神测试覆盖当前输入变化、零值、极小值、移除与恢复；政体测试覆盖显式修正、隐藏修正和原生百分点格式。阵营探针分别在领袖与成员国家上下文读取来源，并依据原版进度计算当前贡献。阶段记录见 expanded_source_checks 和 faction_source_checks。

0.1.5 修复原版匿名对象列表的解析：此前五个文件的 optional_assets 列表会导致整个文件解析失败，苏联、日本等国的动态精神因此被误判为无法确认作用域。另接入当前国家上下文可核实的启用条件与原版动态名称。新增测试逐绑定检查来源函数和实际完整悬停文本，防止只验证叶子函数而遗漏分组输出；跳过的条件或外部输入单独保存在 dynamic_scan_excluded，不计作通过。解析器另有六条回归用例。

领袖来源改用当前 ROOT.GetLeader 显示姓名，测试明确核对“领袖名：元首：数值”。其他类型不增加类别前缀。

变量动态来源读取原版当前输入变量，不是引擎缓存的逐来源贡献。测试中把德国补给消耗输入从 0.15 改为 0.20 而不重算缓存，来源行显示 +20.0%，合计仍为 +15.0%；这明确复现了游戏日更前的短暂不同步。国家合计仍由 ROOT.modifier@ 读取。正式模组不强制更新动态修正缓存，无法核实的来源及差额保持隐藏。测试覆盖原始值 0.00001 显示 +0.001%；低于当前显示精度的值仍会省略。

首次 0.1.1 引擎运行发现超长的候选来源文本会遗漏后段来源，已改为每层最多 8 个分支、只展开含有效来源的分组；最终结果以本报告引用的最新日志为准。普通来源显示修正名和数值；领袖来源增加实际领袖姓名，不添加类别前缀、残差、未知来源或零值行。

错误日志还存在本机启动时已有的 DLC checksum 提示，未将其算成本模组错误。首次试跑发现的网格 `UPPER_LEFT` 大小写及测试附加模组 BOM 问题已修复；120 个动态修正 token 和 94 个科技来源查询 token 已按引擎提示注册。

科技撤销样例中，直接 has_tech 查询仍为真，但 researched_techs 数组已正确移除该项；生产条件同时检查两者，来源行已随实际贡献一起隐藏。顾问 token 查询采用有条件求值，避免尚未创建的角色触发无效 idea 查询。
