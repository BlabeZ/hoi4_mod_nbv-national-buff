# 国家全局 BUFF 统计模组需求建议

整理日期：2026-10-25。基准游戏：**Operation Postern v1.19.3.0.c01a (5632)**。

目标是让玩家在游戏中打开一个独立窗口，按政治、工业、陆军、海军、空军、情报六类查看当前国家持有的修正合计。词条范围采用已整理的 **559 项名单**，其中 A 档 521 项、B 档 38 项。完整条目见 [修正清单](01-buff-catalog.md)，后续生成配置使用 [展示名单 JSON](data/buff-display-whitelist.json)。

建议采用 **KR 中欧同盟式右侧入口与独立浮动窗口，结合 BUFF UI 版的分类列表和国家修正读取方式**。保留两者适合统计页的结构，重新建立词条映射、格式与刷新逻辑。

第一节为用户已确认的统计与交互要求，后续各节展开其实现和验收。此后用户要求“按照要求进行 mod 制作”，已据此制作 [本地测试版](../../hoi4-national-buff/README.md)，采用本需求中的右侧入口、窗口拖动和零值筛选方案。此文保留需求基线，实际完成程度与未通过的验收项见 [测试报告](../../hoi4-national-buff/TEST-REPORT.md)。

### 同名词条的处理

`attrition` 用于国家陆军师损耗；`attrition_for_controller` 当前只找到州／地方使用，继续排除。炎热损耗采用 `heat_attrition_factor`；基础项 `heat_attrition` 当前只找到地方天气赋值，继续排除。这是本轮基于来源对象的选择，不表示引擎必然禁止这些键出现在国家作用域。

冬季损耗基础项与比例项、陆军训练时间基础项与比例项、常规投降界限与强制阈值分别显示，不能因中文名称相同而合并相加。四种建设速度使用国家键，同名的 `state_` 键不加入。

设计商相关排除只针对上述具体对象和科研项目，不排除所有由科技提供的普通国家修正。某工业企业的普通国家修正已经汇入国家合计时，不能通过 `ROOT.modifier@` 单独扣除该来源。详见 [统计方法与边界](../vanilla-modifier-catalog/global-buff-review/methodology.md)。

## 二 统计与取数方式

| 编号 | 要求与实现建议 | 实现与验收含义 |
|---|---|---|
| D01 | 读取引擎维护的国家合计 | 以 `player_context` 的根玩家国家为取数对象，使用 `ROOT.modifier@修正键` 候选路径；每个键独立核验 |
| D02 | 名单驱动展示 | 从同一份名单生成名称映射、分类列表与数值表达式，避免手工维护多套名单造成错配 |
| D03 | 同时显示正负修正 | BUFF 页包含增益和减益；负值不因名称为 BUFF 而过滤 |
| D04 | 区分修正分量和最终属性 | 容量、上限、训练时间等不能直接把返回的修正分量标为最终数量或总时间；需要基值的指标必须另行确认公式 |
| D05 | 保留条件 | 核心领土、特定军种、任务、气候、DLC 等条件放入名称补充或提示，不能把条件加成描述成无条件生效 |
| D06 | 不重复累计来源 | 不再遍历国策、民族精神、科技、领袖、法案、顾问逐项相加；这些来源用于确定词条范围与核验，游戏中的合计由引擎维护 |
| D07 | 不把零读数视为接口验证成功 | 返回 0 可能是真正零值，也可能是当前条件未生效或读取有问题；必须通过已知变化量测试辨别 |

现有两种 BUFF 模组都使用人工维护的名单和 `modifier@` 读取，并没有自动枚举全部修正，也没有拆出每个来源的贡献。[两版 BUFF 取数分析](../08-buff-visualization-mods.md)及 [原版国家 modifier 文档](<E:/Steam/steamapps/common/Hearts of Iron IV/documentation/dynamic_variables_documentation.md:496>)支持采用这一取数基础。

当前名单已经包含领袖、法案与顾问授予国家的代表性修正：国家领袖特质可授予政治点数、战争支持和占领治理修正；`silent_workhorse`顾问授予政治点数系数，`captain_of_industry`授予建设速度；自由贸易法包含产出、建设和科研修正，征兵法包含可征募人口。它们按同一修正键进入国家合计，不建立“领袖版／法案版／顾问版”重复行。[领袖特质](<E:/Steam/steamapps/common/Hearts of Iron IV/common/country_leader/00_traits.txt:13723>)、[顾问特质](<E:/Steam/steamapps/common/Hearts of Iron IV/common/country_leader/00_traits.txt:8320>)、[贸易法](<E:/Steam/steamapps/common/Hearts of Iron IV/common/ideas/_economic.txt:1232>)、[征兵法](<E:/Steam/steamapps/common/Hearts of Iron IV/common/ideas/_manpower.txt:3>)。

### 数值格式

每项至少需要明确显示单位、原始值到显示值的换算、精度、正负号、收益方向。百分比、百分点、固定数值、天数、数量不能混用；`_factor` 后缀和旧模组的格式表达式只可作为检查线索，不能代替验证。

红绿颜色必须与原版一致，优先复用原版文字颜色定义或对应格式规则，不自行选择近似RGB色。收益方向也按该修正在原版中的含义核对：例如成本下降和收益上升可能都显示为有利。不能仅凭数值正负判断颜色，也不能仅凭 `_factor` 后缀判断。尚未确认方向的开发候选先用中性色并登记待核验，不能将该状态视为已满足最终配色验收。零值和中性项沿用原版的中性呈现规则；不显示负零，不把有意义的小数变化舍入后当作零隐藏。

原版字体定义支持本地化颜色标记`§G`、`§R`和重置标记`§!`，且不同字体可覆写颜色，因此应复用所用原版字体的配色。数值提示方向则逐键核对：工厂产出的原版格式为`$RIGHT|+=%1$`，政治顾问花费为`$RIGHT|-=%1$`。原版使用黄色中性提示的项不强制改为红绿。[原版颜色定义](<E:/Steam/steamapps/common/Hearts of Iron IV/interface/core.gfx:796>)、[字体颜色覆写](<E:/Steam/steamapps/common/Hearts of Iron IV/interface/core.gfx:1130>)、[工厂产出格式](<E:/Steam/steamapps/common/Hearts of Iron IV/localisation/simp_chinese/modifiers_l_simp_chinese.yml:653>)、[顾问花费格式](<E:/Steam/steamapps/common/Hearts of Iron IV/localisation/simp_chinese/modifiers_l_simp_chinese.yml:1009>)。

国家返回值包含基值还是只包含修正，需要逐键确认。没有公式依据时使用“修正”标签，保留原始读数供开发核验，不自行补上 1、100% 或假定默认容量。

## 三 界面要求与建议方案

### 入口和独立窗口

| 编号 | 要求或建议 | 交互结果 |
|---|---|---|
| U01 | 游戏右侧独立入口 | 使用明确的 BUFF 统计图标及提示；查看统计不以打开政治页面为前置步骤 |
| U02 | 一个独立主窗口 | 点击入口打开；再次点击、窗口 X 或 Esc 关闭；关闭后立即释放窗口遮挡 |
| U03 | 可拖动并可点击前置 | 默认位置在可见区域内；窗口移动不改变入口位置；关闭按钮和底部控件不能因缩放变得不可达 |
| U04 | 顶部六个页面按钮 | 窗口顶端按政治、工业、陆军、海军、空军、情报顺序横排按钮；点击后切换同一窗口的内容区，并高亮当前页面按钮；首次政治页，关闭记页，再次打开恢复 |
| U05 | 高优先级三列，低优先级四列 | 每页先显示高优先级三列网格，再显示低优先级四列网格，共用纵向滚动区域；每格包含名称和数值，长名称提供完整提示；两区不能按行交错混排 |
| U06 | 默认隐藏已确认零值 | 提供“显示全部／仅非零”切换；“全部”仅指 559 项名单，不含 C 档；待读取确认项不能伪装成零值 |
| U07 | 手动刷新按钮 | 当前分类、显示筛选保持不变，重新获取显示值并更新列表；如无法保留滚动位置，应采用可预测的行为 |
| U08 | 仅当前国家并随tag刷新 | 标题显示当前玩家国家或国旗；外交目标不改变统计对象；tag改变后重新绑定国家并刷新，不提供外国查看或比较功能 |
| U09 | 简洁的条目提示 | 普通提示说明作用和适用条件；技术键、源文件行号、A/B 证据等级放在开发调试模式或离线文档中 |

顶部页面按钮固定在窗口顶端，不随下方词条区域滚动。每次只展示一个分类页面；点击其他页面按钮时，同步切换该页的高优先级三列区和低优先级四列区，刷新当前国家的对应数值。恢复上次页面时，按钮高亮和内容页必须一致。

推荐复用 KR 的入口挂载、独立主窗口、开关与拖动机制，并采用 BUFF UI 的“分类数组 → 条目模板 → 动态文字”结构。KR 的会议、投票、政治点数及成员国系统不属于统计页需求。[KR 界面结构](../07-kaiserreich-mitteleuropa-gui.md)、[BUFF UI 独立页面](../08-buff-visualization-mods.md)。

`raid_filter` 是当前 KR 案例使用的右侧父容器，依赖当前原版布局和其他界面模组的改动。建议把它作为入口原型的首选候选，先验证原版及 KR 环境中的存在性、可见性和位置；发生重叠时，通过入口偏移配置或兼容补丁调整。不能将“使用独立文件”直接写成“与所有 UI 模组兼容”。

### 优先级与三四列布局

当前沿用既有重要度：**P0/P1 为高优先级，共198项；P2/P3 为低优先级，共361项**。这是一份可复查的初始映射，用户要求的是高低分区与列数；后续调整词条重要度时只改映射，不改变三列在前、四列在后的规则。A/B继续表示来源证据，与优先级独立。

各分类先按P0、P1、P2、P3排列，同级按稳定技术键顺序。界面不因数值升降而自动跳动排序；零值筛选仅在所在优先级区内移除条目，不能将低优先级提升到高优先级区。高优先级区无可见条目时可收起空区，剩余低优先级仍使用四列。列数不随当前条目数量改变；末行不足列数时自然留空。

### 页面记忆与国家切换

这里的“页面”指六个分类页，不要求恢复具体滚动位置。无有效记录时初始化为政治页；X、Esc、再次点击入口及其他程序性关闭应经过同一关闭效果，先记录当前页再关闭。重新打开时恢复有效记录，并读取当前国家的新值；记录失效时才回退到政治页。

页面选择与国家数值缓存分开管理。切换tag不应把上一次国家的数值带到新国家；窗口打开时建议保持正在查看的分类并立即重新绑定新国家，关闭时发生tag变化则在下次打开前完成重新绑定。跨tag或跨存档是否共用同一个页面记忆属于实现选择，不能把国家脚本变量声称为纯客户端偏好；至少保证同一国家正常关闭、重开恢复页面。

自由文本搜索、收藏、分组折叠、可选排序和窗口位置恢复列为后续增强；分类页面记忆已经是必需项，不再列为增强项。其中自由文本输入及筛选需要先确认可用的游戏 GUI 接口；本机离线 HTML 有搜索功能，不代表游戏内已经能直接复用。

## 四 实时刷新要求

“实时”应指显示在引擎更新国家修正后能够及时读取新的值，并让持续打开的窗口更新。它不表示重新计算全部来源，也不应在未测试前承诺每帧更新。

| 编号 | 场景 | 必须满足的行为 |
|---|---|---|
| R01 | 打开窗口 | 首次政治页，后续恢复上次关闭页；取当前国家的新值，不沿用上次打开时的旧样本 |
| R02 | 切换分类、切换零值筛选 | 刷新列表成员和数值，标签与实际内容一致 |
| R03 | 手动刷新 | 引擎已应用变化后，下一次可见 GUI 更新应显示新值；暂停时也可通过交互触发读取 |
| R04 | 关闭窗口 | X、Esc、再次点击入口均先记录当前页，再更新显隐状态；若绑定 `dirty`，关闭路径也必须改变刷新变量 |
| R05 | 窗口持续打开 | 国策完成、民族精神获得或失去、动态精神变化、科技／法案变化、领袖更替、顾问任免等改变国家值后，存在自动更新路径 |
| R06 | 重新读档或切换tag | 检测根玩家国家变化，重读国家标题、数值、条件和零值筛选；窗口打开时不能等到重新开窗或推进游戏时间后才清除旧国家数据；关闭时确保重开首帧不沿用旧数据 |

优先用小规模原型比较两种方式：允许可见内容按 Scripted GUI 默认节奏更新，或通过 `dirty` 变量控制刷新。原版文档说明默认每 tick 更新；绑定 `dirty` 后只在变量变化时更新。游戏 tick 不等于屏幕渲染帧，也不等于可直接承诺的现实秒数。[原版刷新说明](<E:/Steam/steamapps/common/Hearts of Iron IV/common/scripted_guis/_documentation.md:102>)。

如果采用 `dirty`，打开、关闭、分类、筛选及手动刷新必须经过同一套刷新效果；还要补上持续打开时的自动更新机制。仅在打开和切类时翻转变量，不能满足 R05。界面状态与数值列表可以分开管理，避免仅因窗口内容更新而无条件重建全部 559 项。

建议将正常时间流动时的自动更新目标设为 **引擎应用变化后不超过 1 个游戏小时**，作为原型测试目标，最终值由暂停行为和性能测试确定。游戏暂停后，定时 `on_action` 不应被当作自动刷新保证；暂停期间至少提供可靠的手动刷新。若默认 GUI 更新能在暂停时持续反映变化，再据实说明其能力。

## 五 性能和状态管理

建议只生成当前分类需要的列表，避免为其他五类持续构建不可见控件。需要周期刷新时，限定为实际打开统计页的玩家国家；不遍历全部国家、州、单位或全部 4,484 个注册键。

窗口开关、当前分类和筛选属于显示状态，不得更改国家修正、民族精神、法律、科技、资源或部队属性。允许为界面使用独立前缀的国家标记、变量和数组；它们仍是游戏脚本状态，不能称为纯客户端设置。

不同国家不应共用一个全局开关或刷新状态。同一国家由多名玩家共同控制时，国家标记可能共享；在未找到并验证客户端隔离方法前，不承诺各客户端拥有独立窗口偏好。观察者模式和切换国家后的行为也需要单独测试。[现有模组状态方式](../08-buff-visualization-mods.md)。

不建议仅为了统计页启用 AI 点击逻辑。性能记录应包含同一存档、相同游戏速度下的关闭／打开窗口对照，至少覆盖条目最多的陆军分类、显示全部模式和高分辨率缩放。

## 六 建议的工程组织

| 部分 | 职责 |
|---|---|
| 展示名单 JSON | 修正键、名称、六类、条件、来源证据及验证状态；作为生成输入，不是游戏直接加载的运行文件 |
| 生成工具 | 为固定名单生成稳定条目编号、本地化映射、分类及高低优先级列表、三四列配置和需要的格式配置；同键不重复生成 |
| `interface` | 入口、主窗口、标签、滚动区域、高优先级三列与低优先级四列网格、条目和图形资源定义 |
| `common/scripted_guis` | 根国家上下文、挂载、显隐、点击回调与列表绑定 |
| `common/scripted_effects` | 开关、页面保存与恢复、分类、列表更新和tag变化后的刷新；不修改玩法数值 |
| `common/scripted_localisation` | 条目编号到文本的映射；必要的动态提示 |
| `localisation/simp_chinese` | 已确认中文名称、单位、说明与数值表达式 |
| `common/on_actions` | 仅在选定刷新方案确有需要时使用，并限制执行对象与频率 |

为容器、控件、变量、数组、效果和本地化统一使用模组自己的前缀。优先以新增文件挂载界面，不替换整份原版 GUI；如果必须覆盖，应在兼容说明中逐项列出文件。不要照搬旧 BUFF 模组的名称错配和重复映射，例如工厂修复／船只修理、非核心攻防等问题。[既有错配记录](../08-buff-visualization-mods.md)。

建议独立提供入口图标和文字，不强制依赖 KR、旧 BUFF 模组或外部图标模组。支持版本、DLC 条件、校验和、铁人／成就及多人兼容结论应以实际模组的测试结果填写，不能由“只显示数值”直接推断。

## 七 开发前必须完成的读取核验

当前 **559 项均未逐项完成游戏内读取验证**。A 档的国家来源证据不能代替接口验证，B 档也不能一律当作不可用。

先选政治、建设、陆海空、情报和条件修正各若干项建立可复现样例，再扩展到全部名单。逐键记录作用域、测试来源、已知输入变化、返回变化、单位／倍率、基值、正负方向、加入与移除后的结果，以及持续打开窗口的刷新表现。

以下五项在当前原版扫描中没有定义赋值，必须单独用受控测试验证：

| 修正键 | 拟显示名称 | 特别检查 |
|---|---|---|
| `air_invasion_division_cap` | 每项空降入侵计划的陆军师容量 | 修正值与最终容量的区别 |
| `air_invasion_plan_cap` | 空降作战计划上限 | 原版中英文说明存在计数对象差异，须确认读数代表计划数量还是师数量 |
| `combat_width_factor` | 己方战场宽度 | 国家分量可读性及作用对象 |
| `dockyard_donations` | 海军船坞捐赠 | 国家分量可读性及数量单位 |
| `training_time_army` | 陆军师训练时间基础项 | 与比例项的区别、单位和默认基值 |

测试通过前，这些项保留在目标名单与开发记录中。不能把读取失败默认为 0 后声称已实现 559 项。若某项不可按国家口径正确读取，应在交付说明中列出未实现项和原因；修改用户已确认名单需留下明确变更记录。

## 八 建议的验收标准

| 验收项 | 通过条件 |
|---|---|
| 名单完整性 | 559 个键唯一且与交付 JSON 一致；六类合计分别为 94、109、166、92、51、47；无名及四个明确移除项不出现 |
| 作用域与来源 | 所有行只指向当前玩家国家；不会随外交目标、选中州或具体单位误切换；领袖、法案、顾问提供的国家修正随加入、替换、移除正确变化，不采集C档地方对象值 |
| 数值与格式 | 每项有验证记录；已知增加、减少和移除测试的读数变化正确，单位、精度、方向及基值处理一致；相同修正的红绿颜色及利弊方向与原版对应表现一致 |
| 同名项 | 冬季损耗、训练时间、投降界限、空海天气惩罚等名称区分清楚，无重复读取后重复展示 |
| 独立界面 | 无需政治页面即可打开；入口、X、Esc开关均有效；拖动、点击前置和滚动可用；顶部六个按钮按既定顺序切换对应页面，当前按钮高亮正确，内容滚动时按钮位置不变 |
| 优先级与列数 | 各页高优先级区位于前方且固定三列，低优先级区在后且固定四列；同级顺序稳定；筛选后不跨区、不变列数 |
| 页面记忆 | 无记录时第一页政治；依次验证X、Esc、入口切换关闭均保存所处分类，重开恢复；记录无效才回退政治页 |
| tag切换 | 窗口打开时切tag后标题、读数、条件和筛选全部来自新国家；暂停切tag也不保留旧国家值；关闭后切tag再打开同样正确 |
| 零值筛选 | 只隐藏已确认零值；正负值均保留；显示全部不会把 C 档、无名或失效占位项带入 |
| 刷新 | 打开、手动刷新、切类、筛选与关闭都正确；持续打开时满足经过测试后确认的自动更新目标 |
| 暂停与读档 | 暂停下手动刷新有效；重载存档和切换国家无旧数值或重复条目 |
| 布局 | 在选定支持的分辨率与 UI 缩放组合中，无入口遮挡、无法关闭、关键文字截断或窗口永久移出屏幕 |
| 性能 | 记录开关窗口的帧率和游戏推进对照，无不必要的全世界扫描或隐藏页面重建 |
| 兼容 | 原版基准先通过；KR及其他目标模组分别给出测试结果，列出入口冲突和补丁条件 |
| 不改变玩法 | 所有界面操作仅影响显示状态，不额外授予或移除任何玩法修正 |

建议布局测试覆盖 1366×768、1920×1080、2560×1440，并在游戏支持且可操作的 100%、125%、150% 缩放组合中记录结果；这是一份测试矩阵建议，不是当前已经支持这些组合的声明。

## 九 建议的实现顺序和首版边界

1. **读取原型**：用少量确定来源的条目验证根国家、数字格式、暂停和刷新路径，同时测试五项无赋值候选。
2. **独立窗口原型**：实现右侧入口、开关、拖动、关闭与六类切换，验证原版及 KR 的入口位置。
3. **完整名单接入**：由交付JSON生成全部条目，加入高三列／低四列分区、原版红绿颜色、页面记忆、条件提示、零值筛选和手动刷新。
4. **持续更新与性能调整**：依据原型选择默认更新或受控 `dirty`，测试自动更新、读档和不同国家。
5. **完整核验与打包**：逐项核验、记录未通过项、完成版本与兼容说明，再形成可分发模组。

首版建议聚焦当前国家的修正合计，不加入外国对比、来源贡献拆分、历史曲线、单位最终属性或自动发现所有模组自定义修正。后续若增加这些能力，需要单独的数据模型和验收规则；目前的 `modifier@` 合计读取不能直接提供它们。
